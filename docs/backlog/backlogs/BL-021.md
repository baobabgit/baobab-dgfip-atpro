# BL-021 - Cadrer et cabler les fichiers CSV reels de reference

Projet : AT Pro Pilotage  
Version cible : `v0.1.0`  
Type : Backlog de livraison  
Statut : pret pour implementation

### Objectif

Corriger le trou de couverture entre fixtures anonymisees et tests sur fichiers CSV reels de reference.

### Dependances

- BL-018
- BL-019

### Taches

1. Creer `docs/reference-data.md`.
2. Documenter les options autorisees pour les CSV reels de reference.
3. Choisir le comportement par defaut pour `v0.1.0` :
   - CI sur fixtures anonymisees ;
   - validation locale optionnelle sur `ATPRO_REFERENCE_CSV_DIR`.
4. Ajouter ou specifier un marqueur de tests `reference`.
5. Ajouter ou specifier une commande de validation locale des fichiers reels.
6. Verifier que l'absence de fichiers reels ne produit pas de faux succes.
7. Verifier que les fichiers reels ne sont pas ajoutes au depot.
8. Mettre a jour l'index du backlog et la synthese de tracabilite.
9. Declarer le marqueur Pytest `reference` dans `pyproject.toml`, section `[tool.pytest.ini_options]`, des que le fichier existe ou que les tests sont ajoutes.
10. Verifier qu'aucun warning Pytest de marqueur inconnu n'est emis.

### Livrables

- `docs/reference-data.md`
- convention `ATPRO_REFERENCE_CSV_DIR`
- tests ou specification de tests `reference`
- declaration du marqueur `reference` dans `pyproject.toml` lorsque l'outillage Pytest est present
- mise a jour de la tracabilite US/FEAT/BL

### Tests

- Test du cas sans dossier reference.
- Test du cas dossier reference vide.
- Test du cas fixtures anonymisees.
- Test optionnel avec fichiers reels si disponibles.
- Verification sans warning Pytest de marqueur inconnu.

### Acceptation

- Le mode de fourniture des CSV reels est tranche ou documente comme decision ouverte bloquante.
- La CI ne depend pas de fichiers reels.
- Une IA de developpement sait comment lancer la validation sur fichiers reels.
- Aucun fichier sous `sources/` ou export sensible n'est modifie.
- Le marqueur `reference` ne genere pas de warning Pytest.
