# US-005 - Parser un fichier d'appels entrants

Projet : AT Pro Pilotage  
Version cible : `v0.1.0`  
Type : User story  
Statut : pret pour implementation


### Objectif

Transformer un CSV d'appels entrants en `Call` et `CallSegment`.

### Donnees attendues

Colonnes typiques :

- `ID de l'appel` ;
- `Numero appelant` ;
- `Numero appele` ;
- `Nom de l'agent` ;
- `Debut d'appel` ;
- `Fin d'appel` ;
- `Flux` ;
- `Service` ;
- `Categorie de qualification` ;
- `Motif de qualification` ;
- `Origine du raccroche` ;
- `Noms de mesures` ;
- `Valeurs de mesures`.

### Scenario nominal

1. Lire les lignes.
2. Normaliser les en-tetes.
3. Identifier les mesures par ligne.
4. Regrouper les lignes par appel et segment.
5. Consolider `Duree de communication`.
6. Consolider `Duree de mise en garde`.
7. Creer un `Call` global.
8. Creer un ou plusieurs `CallSegment`.
9. Conserver les numeros de lignes sources.
10. Signaler les appels multi-segments.

### Scenarios alternatifs

- Colonnes dans un ordre different.
- Dates au format `dd/MM/yyyy HH:mm:ss`.
- Dates au format `dd-MM-yy HH:mm:ss`.
- Agent vide ou non reconnu.
- Duree de communication egale a zero.
- Appel avec plusieurs agents.

### Criteres d'acceptation

- Ne jamais supprimer une ligne de mesure comme doublon.
- Un appel avec deux mesures produit un segment consolide.
- Un appel avec plusieurs agents produit plusieurs segments ou un avertissement explicite selon les donnees disponibles.
- Les numeros de telephone sont hashes ou masques dans les sorties de diagnostic.
