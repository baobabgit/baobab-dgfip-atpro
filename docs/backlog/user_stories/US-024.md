# US-024 - Gerer les conflits et politiques de mise a jour

Projet : AT Pro Pilotage  
Version cible : `v0.2.0`  
Type : User story  
Statut : pret pour implementation

### Objectif

En tant qu'administrateur fonctionnel futur, je veux que les donnees deja presentes mais modifiees soient traitees par une politique explicite afin d'eviter les ecrasements silencieux.

### Scenario nominal

1. Detecter une cle metier deja presente.
2. Comparer l'empreinte normalisee.
3. Identifier si la donnee est identique ou modifiee.
4. Appliquer la politique par type de donnee.
5. Journaliser la decision.
6. Marquer les statistiques futures comme invalidables si necessaire.

### Criteres d'acceptation

- Identique : skipped.
- Ticket modifie : update autorise selon politique.
- Appel modifie : conflit ou rejet par defaut.
- Activite modifiee : conflit par defaut.
- Toute decision est tracable.
