# US-014 - Cadrer l'architecture de persistance v0.2.0

Projet : AT Pro Pilotage  
Version cible : `v0.2.0`  
Type : User story  
Statut : pret pour implementation

### Objectif

En tant qu'IA de developpement, je veux disposer d'une decision d'architecture claire pour la persistance afin d'introduire PostgreSQL, SQLAlchemy et Alembic sans casser le package Python `atpro` livre en `v0.1.0`.

### Scenario nominal

1. Lire `ADR-0001`.
2. Lire le cahier des charges sections persistance et roadmap `v0.2.0`.
3. Confirmer que `src/atpro` reste le coeur Python pour `v0.2.0`.
4. Definir les frontieres `domain`, `application`, `infrastructure.database`, `interfaces.cli`.
5. Definir les dependances autorisees par couche.
6. Creer une ADR de persistance `ADR-0002`.
7. Mettre a jour les contrats et la matrice d'integration.

### Criteres d'acceptation

- Une ADR `docs/architecture/adr/ADR-0002-persistance-postgresql-v020.md` existe.
- L'ADR confirme ou modifie explicitement la structure `src/atpro`.
- Les modeles du domaine restent independants de SQLAlchemy.
- Les repositories et Unit of Work sont dans une couche infrastructure/application.
- Le perimetre hors `v0.2.0` reste documente : statistiques, API, React, rapports.
