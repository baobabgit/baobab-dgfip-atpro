# US-021 - Persister les tickets

Projet : AT Pro Pilotage  
Version cible : `v0.2.0`  
Type : User story  
Statut : pret pour implementation

### Objectif

En tant qu'IA de developpement, je veux enregistrer les tickets issus du parseur sans doublons et avec une politique explicite de mise a jour des champs evolutifs.

### Scenario nominal

1. Creer la table `ticket`.
2. Ajouter la cle unique `source_system`, `external_ticket_id`.
3. Mapper les agents et sites bruts ou rapproches.
4. Persister les dates et statuts.
5. Gerer le cas d'un ticket deja connu mais modifie.
6. Tester import identique, import modifie et ticket ouvert.

### Criteres d'acceptation

- Reimporter un ticket identique ne cree pas de doublon.
- Un ticket modifie est traite selon la politique configuree.
- Les champs sensibles de contact ne sont pas stockes en clair.
- Les dates incoherentes restent rejetees ou signalees.
