# US-001 - Initialiser le socle de developpement v0.1.0

Projet : AT Pro Pilotage  
Version cible : `v0.1.0`  
Type : User story  
Statut : pret pour implementation


### Objectif

Mettre le depot dans un etat coherent pour commencer le developpement du package `atpro`.

### Acteur principal

IA de developpement.

### Pre-conditions

- Le cahier des charges existe.
- `AGENTS.md` existe ou le workflow du depot est connu.
- Le depot peut contenir un squelette template comme `example_package`.

### Declencheur

Demarrage du lot `v0.1.0`.

### Scenario nominal

1. Lire `AGENTS.md`.
2. Lire le cahier des charges.
3. Identifier la structure actuelle du depot.
4. Rediger une ADR sur la structure retenue pour `v0.1.0`.
5. Remplacer le squelette template par `atpro`.
6. Creer l'arborescence minimale du package.
7. Creer l'arborescence minimale des tests.
8. Configurer ou verifier les commandes de validation.
9. Initialiser le backlog si le workflow du depot utilise `queue.yaml`.

### Scenarios alternatifs

- Si `AGENTS.md` impose un format mono-package, conserver `src/atpro` a la racine et documenter la transition future vers monorepo.
- Si le depot possede deja `backend/`, placer le package dans `backend/src/atpro` seulement si une ADR le valide.
- Si `queue.yaml` n'existe pas, ne pas le creer sans besoin du workflow, mais documenter le backlog dans `docs/backlog/backlogs/`.

### Resultats attendus

- ADR presente.
- Package `atpro` present.
- Ancien package template supprime ou ignore selon regles du depot.
- Tests importables.
- Commande de validation Python executable.

### Criteres d'acceptation

- Le package `atpro` est importable.
- Le nom `example_package` n'est plus utilise par le code applicatif.
- La decision de structure est documentee.
- Aucun fichier sous `sources/` n'a ete modifie.
