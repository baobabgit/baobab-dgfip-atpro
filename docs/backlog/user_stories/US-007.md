# US-007 - Parser un fichier tickets

Projet : AT Pro Pilotage  
Version cible : `v0.1.0`  
Type : User story  
Statut : pret pour implementation


### Objectif

Transformer un CSV tickets en objets `Ticket`.

### Donnees attendues

Colonnes typiques :

- `Numero Ticket` ;
- `Date-Heure Prise en Charge Ticket` ;
- `Date-Heure Creation Ticket` ;
- `Date-Heure Resolution Ticket` ;
- `Date-Heure Cloture Ticket` ;
- `Type Canal Ticket` ;
- `Nature Ticket` ;
- `Type Ticket` ;
- `Statut Ticket` ;
- `Site Repartition Ticket` ;
- `Nom Agent Qualification Ticket` ;
- `Prenom Agent Qualification Ticket` ;
- `Site Agent Qualification Ticket` ;
- `Nom Agent Resolution Ticket` ;
- `Prenom Agent Resolution Ticket` ;
- `Site Agent Resolution Ticket` ;
- `Nom Agent Cloture Ticket` ;
- `Prenom Agent Cloture Ticket`.

### Scenario nominal

1. Detecter le schema tickets.
2. Gerer les variantes longues et reduites.
3. Lire les lignes.
4. Normaliser les dates.
5. Normaliser les statuts, canaux, natures et types.
6. Construire les identites agents brutes.
7. Construire les sites bruts.
8. Masquer ou hacher les identifiants de contact.
9. Produire les objets `Ticket`.
10. Signaler les dates incoherentes.

### Scenarios alternatifs

- Ticket ouvert sans date de resolution.
- Ticket ouvert sans date de cloture.
- Colonnes contact presentes dans un schema mais absentes dans un autre.
- Encodage degrade.
- Agent de resolution absent.
- Site absent.

### Criteres d'acceptation

- Les schemas tickets historiques sont reconnus.
- Un ticket sans resolution reste valide si son statut est compatible.
- Une resolution anterieure a la creation genere une erreur ou un avertissement severe.
- Les emails et numeros de telephone ne sont pas stockes en clair dans le modele analytique.
