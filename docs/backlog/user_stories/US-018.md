# US-018 - Persister les referentiels agents, sites, alias et affectations

Projet : AT Pro Pilotage  
Version cible : `v0.2.0`  
Type : User story  
Statut : pret pour implementation

### Objectif

En tant qu'IA de developpement, je veux enregistrer les sites, agents, alias et rattachements de maniere idempotente afin que les imports puissent rapprocher les donnees sans doublons.

### Scenario nominal

1. Creer les tables `site`, `agent`, `agent_alias`, `agent_site_assignment`.
2. Ajouter les contraintes d'unicite.
3. Implementer les repositories.
4. Ajouter des methodes `get_or_create`.
5. Gerer les collisions d'alias.
6. Tester l'idempotence.

### Criteres d'acceptation

- Rejouer deux fois le meme referentiel ne cree pas de doublon.
- Les alias normalises sont uniques.
- Les affectations datees ne se chevauchent pas sans signalement.
- Les donnees brutes utiles restent tracables.
